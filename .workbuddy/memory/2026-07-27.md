# 2026-07-27 工作日志

## 修复：AI清理「扫描」界面卡死
- 根因：`src/main/aiCleanup.ts` 的 `scanAiCleanup`（`scan-ai-cleanup` IPC）在主进程用 `fs.readdirSync/statSync` 做**同步深度递归**遍历磁盘。
  1. Windows junction/重解析点（如 `AppData\Local\Application Data` 指回 `AppData`）无环路检测 → 无限递归，主线程卡死。
  2. `dirSize` 无目录/文件数量上限且从不让出主线程 → 大目录扫描时主线程长期阻塞，窗口被 Windows 标记「未响应」。
- 修复：将 `dirSize`/`recycleBinSize`/`tempSize`/`browserCacheSize`/`scanLargeOldFiles` 改为 **async**，每 ~256 项 `await setImmediate` 让出主线程；用 `fs.promises.realpath` 的 realpath 访问集合 + `MAX_SCAN_DEPTH=60` + `MAX_SCAN_DIRS=50000` 切断 junction 环路与失控遍历；递归目录前 `entry.isSymbolicLink()` 跳过符号链接。`scanAiCleanup` 内相应 `await`。
- 验证：`tsc -p tsconfig.node.json --noEmit` 通过（EXIT 0）。渲染进程未改动（`AiCleanup.tsx` 扫描期间本就禁用按钮+转圈）。
- 注：因沙箱 safe-delete shim，`vite build` 仍无法跑；类型检查用托管 node 跑项目自带 tsc 即可。

## 修复：ETW process exited with 1 / 老不可用降级快照模式
- 根因：`src/main/processTracker.ts` 的 ETW 实时文件监听用 `Microsoft-Windows-Kernel-File` 提供程序，其启用命令 `wevtutil sl ... /e:true` **必须以管理员身份运行**。普通用户启动 AgentSC 时该步静默失败 → `Get-WinEvent -Oldest` 无法建立实时订阅 → PowerShell 退出码 1 → 每次启动都走 `startEtwTracking` reject（`ETW process exited with 1`）→ 落到快照模式。即「老不可用降级快照模式」。
- 修复：新增 `isElevated()`（用 `net session` 退出码判断提权），`startProcessTracking` 启动时先检测：非管理员直接 `startSnapshotTracking()` 并记清晰 info 日志 + 把 `lastError` 设为「需要管理员权限才能启用 ETW 实时监听，已使用快照模式」，避免无意义的 ETW 尝试、3 秒等待与"exited with 1"噪声；管理员仍照常启用 ETW。
- 验证：`tsc -p tsconfig.json --noEmit` EXIT 0。
- 后续可选：若用户要真正的实时 ETW，需让进程以管理员身份运行（electron-builder `requestedExecutionLevel=requireAdministrator` 或启动时 `runas` 重新提权）——本次未做，因会让整个 app 常驻管理员。

## 需求：默认管理员模式启动
- 用户确认要让 AgentSC「默认以管理员身份启动」。在 `package.json` 的 `build.win` 增加 `"requestedExecutionLevel": "requireAdministrator"`（electron-builder 会将该清单嵌入打包后的 exe）。
- 效果：打包安装后，每次双击启动都走 UAC 提权、主进程常驻管理员 → `isElevated()` 恒为真 → ETW 实时监听生效（不再降级快照）。
- 注意：`requireAdministrator` 仅作用于**打包后的 exe**；`npm run dev`（vite-plugin-electron 拉的 dev electron）不受此清单影响。Dev 想测 ETW 需手动用「管理员终端」跑 `npm run dev`，否则仍走快照（上一轮的 `isElevated()` 降级逻辑会给出清晰提示，不会刷 exit 1 噪声）。
- 未做运行时 self-elevation（`runas` 重新拉起）：因 dev 下 vite-plugin-electron 会监控 electron 进程退出并重启，自提权退出会触发无限重启循环，故仅在打包场景用清单解决。
